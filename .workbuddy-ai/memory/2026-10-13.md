## OC 记录站（OC Wiki）技术调研与方案

- **需求**：类 Wiki 的原创角色（OC）记录网站，六个板块——总览 / 世界观 / 人物档案 / 论坛 / 画廊 / 故事收录；
  UI 要求低饱和、整洁干练，多主题（蓝白、黑红等）。皇上要求**先出方案、确认后再写代码**。
- **调研对象（9 个同类开源项目）**：
  - A 类 OC/世界观专用：LoreFolio（Next.js + localStorage，无协议）、OC Studio（Next.js + Dexie + Tauri，MIT）、
    Chronicle Keeper（Rust + Tauri + Markdown，MIT）
  - B 类 画廊/展示：Sona（SvelteKit + Cloudflare D1/R2，Apache-2.0）、AnimaDex（Flask + SQLite）、
    OC_demo（纯原生 HTML/CSS/JS，BSD-3）
  - C 类 通用 Wiki：Wiki.js（Node + Vue，AGPL）、Kanka（Laravel + Vue + MySQL，source-available）
  - D 类 静态模板：Eleventy OC Directory Template（11ty + Nunjucks，MIT）
- **核心结论**：没有可直接复用的项目。最贴近的 LoreFolio / OC Studio 都是**单机本地工具**（无服务端、无论坛）；
  Kanka 功能最全但 **Laravel 技术栈重 + 许可非标准开源**。策略 = **自建主站 + 分模块借鉴**。
- **推荐架构**：Astro 5 静态优先 + Content Collections（Zod 校验）+ 自研设计令牌主题系统（参考 Sona 的
  「主题→生成 CSS→对比度校验」流程）；**论坛解耦为可插拔模块**，三级升级路径：
  轻量讨论（Waline/Twikoo/Giscus）→ 半自建（Workers+D1 / Supabase）→ 成熟系统（Flarum/Discourse）。
- **借鉴清单**：LoreFolio 档案分类与概览页 / OC Studio 数据模型与内链 / Chronicle Keeper 的「Markdown + 双链」/
  Sona 主题令牌与画廊 / 11ty 模板的命名空间式 IA 与内容警告 / OC_demo 的视觉质感（毛玻璃、聚光灯、可拖拽导航）。
- **产出**：`D:\vibecoding\oc\OC-WIKI-实现方案.md`
  （需求拆解 / 项目调研 / 横向对比表 / 借鉴清单 / 架构 / 技术选型 / IA / 数据模型 / 主题令牌示例 / M1-M3 路线图 / 决策点 / 风险）。
- **待皇上拍板的 4 个决策点**：① 论坛形态 ② 作者是一人还是多人 ③ 是否多用户 ④ 部署目标（公网/内网）。

## 决策落定 + 第一版实现（同日）

- **皇上拍板**：自用 + 本地搭建 + 记录用途；论坛是「创作者自己写内容、预置几个自带的」，需要发帖功能，
  发帖时能选人物头像 / 账号名字 / 内容。追加两条：人物档案要**关系图**页，世界观要**时间线**页。
  再追加：UI 主题要**可切换**且**多做几种配色**。
- **架构因此简化**：砍掉「论坛独立服务」，改为**纯前端本地应用**——无后端、无账号、无网络请求。
- **最终技术栈**：Vite 8 + React 19 + TS + Tailwind v4（CSS-first）+ React Router 7（**HashRouter**，
  静态部署/双击 dist/index.html 都能跑）+ Dexie 4（IndexedDB）+ @xyflow/react 12（关系图）+ lucide-react。
- **主题系统设计（关键复用点）**：`src/styles/theme.css` 里每套配色**只定义 5 个种子色**
  （`--seed-accent/bg/surface/ink/line`），其余 15 个令牌全部用 `color-mix()` 派生；
  浅色写 `[data-theme='x']`，深色写 `[data-theme='x'].dark`。
  现有 8 套：蓝白 / 黑红 / 墨绿 / 藤紫 / 琥珀 / 青瓷 / 藕荷 / 石墨。
  加新配色 = 加 10 行 CSS + 在 `src/lib/theme.tsx` 的 `PRESETS` 登记一条。
- **踩坑记录**：
  - TypeScript 新版本**移除了 `tsconfig` 的 `baseUrl`**，`paths` 必须写相对路径 `./src/*`。
  - `vite.config.ts` 用 `node:url` 需装 `@types/node` 并加进 `types`。
  - 时间线年份标签用绝对定位时，`left-0` 是相对**每个条目**而非外层容器——把 `pl-[112px]`
    挪到条目上才对，否则年份会压住标题。
  - 首字头像用「浅色底 + 同色字」在深色主题下对比度过低 → 改成**实色圆底 + 白字**。
- **验证方式**：`tsc --noEmit` 通过；`vite build` 通过（2108 模块，CSS 49.9 kB）；
  用 `mcp__streamable-mcp-server__chrome_*` 打开 `vite preview` 逐页截图确认
  （总览/论坛/时间线/关系图/画廊/角色详情 + 深色黑红主题），控制台**零异常**。
  ⚠️ `agent-browser` 在本机反复卡死（open/screenshot 超时），**改用 chrome MCP 工具链**更可靠。
- **产出**：完整可运行项目在 `D:\vibecoding\oc\`（`npm run dev` → http://localhost:5273）。
  含 README.md。页面：总览 / 世界观（词条+时间线）/ 人物档案（列表+详情+关系图）/
  论坛（板块+帖子+以 OC 身份发帖+预置 4 帖）/ 画廊（瀑布流+灯箱）/ 故事收录 / 设置（8 套主题+导入导出）。

## 布局重构：顶部主导航 + 侧栏详细分类（同日）

- **皇上要求**：「总览、世界观、人物档案、画廊、故事收录、论坛、设置这种放在头顶导览，侧面导览用来详细分类」。
- **做法**：
  - 新建 `src/components/SideNav.tsx`：按 `pathname` 前缀切换 7 套侧栏
    （OverviewSide / WorldSide / CharacterSide / GallerySide / StorySide / ForumSide / SettingsSide）。
  - 重写 `Layout.tsx`：顶部 `MainNav`（7 个主板块）+ 桌面端 `aside w-[208px] sticky` + 移动端抽屉。
  - 新建 `ThemeMenu.tsx`（顶部配色下拉，替代原先放在侧栏的主题选择器）。
  - 新建 `src/lib/useParam.ts` 的 `useParamState(key)`：把筛选条件同步到 URL query。
  - `Worldview / Gallery / Stories / Forum` 四个页面改为**从 URL query 读筛选**（`?cat` `?char` `?status` `?board`）。
  - 删除 `SectionTabs.tsx`（被侧栏导航取代）；`Settings.tsx` 四个 section 加 `id` + `scroll-mt-20` 供侧栏锚点。
- **重要坑（侧栏筛选）**：侧栏链接必须用 **id**（`?board=board-notice`），不能用名字；
  手填名字会得到「0 个帖子」的假 bug。多维筛选时链接要**保留其他 query**（StorySide 里的 `link()` 做了 patch 合并），
  否则点一个维度会把另一个维度清掉。
- **验证**：chrome MCP 逐路由采样 DOM —— 9 条路由 h1 与侧栏内容全部正确；
  多维筛选（世界观+状态）叠加正常，「全部」只清当前维度；控制台 0 异常。
  ⚠️ `chrome_screenshot` 有时会抓到**另一个窗口**的标签页（本机同时开了两个 Chrome 窗口），
  截图前必须显式传 `windowId` + `tabId`；另外 `fullPage: true` 抓出来的图会缺 sticky 顶栏/侧栏，用 `fullPage: false`。

## 故事收录：新增「所属世界观」（同日，含一次返工）

- **第一版**：按「分别增加世界观选项和世界观章节选项」实现，给 `Story` 加了 `worldId` + `chapter` 两个字段。
- **皇上随即改口**：「世界观章节去掉，故事收录的时候可以选择世界观」→ **保留 `worldId`，删掉 `chapter`**。
- **最终形态**：
  - `Story.worldId?: string`（指向 `WorldEntry.id`）。
  - `StoryEditor`：一个「世界观」下拉，按词条层级缩进展开（`　`+`└ ` 前缀 + 分类后缀）。
  - `SideNav.StorySide`：状态 / **世界观** 两组筛选，链接保留其他 query。
  - `Stories.tsx`：`?world=` 筛选 + 可清除 chip + 卡片显示世界观名；`StoryDetail` 侧栏加「世界观」卡片（可跳词条）。
- **数据迁移**：`seed.ts` 里加了 `backfillStoryWorld()` —— 用 `db.settings` 的标记位只跑一次，
  给示例故事补 `worldId`，并用 `.modify()` + `delete rec.chapter` **清掉已废弃的 chapter 键**
  （注意：Dexie 的 `update(id, {k: undefined})` 不会真删键，必须用 `modify` + `delete`）。
- **踩坑**：绕过 Dexie 直接操作 IndexedDB 删数据后，`useLiveQuery` **不会感知变更**，界面仍显示旧条数——
  需要刷新页面。测试清理数据时要记得这一点，否则会误判成"没删掉"。
